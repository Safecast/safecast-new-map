Safecast Admin Help

This guide explains every admin tab, page, and data table. Use the table of contents on the left to jump to a section, or scroll through. All admin pages share a common tab bar at the top for navigation between sections.

Access & Authentication

Admin pages can be accessed in two ways:

  • Session login: Log in with an account that has the Admin flag set. The admin tabs appear automatically once you are authenticated.
  • URL password: Append ?password=YOUR_ADMIN_PASSWORD to any admin URL. This is forwarded automatically as you navigate between tabs.
Note: The URL password method is useful for direct links and API testing, but session-based login is recommended for regular use.

Admin pages always send Cache-Control: no-cache headers so CloudFront never serves a stale admin view.

Users Tab

Manage all registered user accounts. Data is loaded server-side with pagination; the table supports per-column filtering within the current page, plus a server-side search across all pages.

Table columns

ColumnDescription
IDAuto-incremented internal user ID.
EmailPrimary login email address. Must be unique.
UsernameOptional display name (max 50 chars). May be blank.
External IDIdentifier from an external identity provider, if any.
API KeyToken used for X-API-Key header authentication on API calls.
StatusActive (green) or Inactive (red). Inactive users cannot log in.
AdminAdmin (purple) or User (grey). Admins can access all admin pages when logged in.
Email VerifiedVerified (green) or Unverified (orange). Unverified users cannot log in until they confirm their email.
CreatedUTC timestamp when the account was created.
Last LoginUTC timestamp of the most recent successful login, or "Never".

Actions

Add User Edit Make Admin / Remove Admin Reset Password Delete Delete Selected
  • Add User — Opens a modal to create a new account. Email and password are required. Status, Admin, and Email Verified flags can be set at creation time.
  • Edit — Opens the same modal pre-filled. Leave the password field blank to keep the existing password.
  • Make Admin / Remove Admin — Toggles admin privileges with a confirmation prompt.
  • Reset Password — Sends a password-reset email to the user's address. Requires SMTP to be configured.
  • Delete — Permanently deletes the user. Cannot be undone.
  • Delete Selected — Appears when one or more checkboxes are ticked; deletes all selected users at once.

Search & filtering

The Search box (top-right) performs a server-side search across email, username, and ID — it queries all pages, not just the current view. The per-column filter inputs in the table header filter only the rows visible in the current page. Combine both for precise results.

Pagination

Use the page-size selector (25 / 50 / 100 / 200) and First / Prev / Next / Last buttons at both the top and bottom of the table to navigate. The page-size selectors are kept in sync.

Tip: Column widths are resizable — drag the right edge of any header to adjust.

Uploads Tab

Browse and manage all files uploaded by users (bGeigie logs, CSV tracks, etc.). Each row represents one upload event.

Table columns

ColumnDescription
IDInternal upload ID.
UserLinked user account, shown as a clickable email address that filters uploads to that user. Shows "Guest" if no account was linked at upload time.
FilenameOriginal filename as uploaded.
TypeDetected file type (e.g. bGeigie log, CSV).
StatusProcessing state: pending, processing, done, or error.
MeasurementsNumber of data points imported from this file.
Uploaded AtUTC timestamp of the upload.
ErrorProcessing error message, if any.

Actions

Edit metadata Import from Safecast API Delete Delete Selected
  • Edit metadata — Update the upload's description or linked user.
  • Import from Safecast API — Fetches historical bGeigie drive logs from the public Safecast API and imports them into the database.
  • Delete / Delete Selected — Permanently removes the upload record and its associated measurements. Cannot be undone.

Filtering by user

Click on a user's email in the User column to filter the list to that user's uploads. A Clear filter link appears at the top when a user filter is active.

Note: Uploads page is rendered server-side (unlike other admin pages which are pure SPAs), so navigation after filtering works via URL query parameters.

MCP Analytics Tab

View analytics data collected from the AI assistant (MCP server). Five sub-tables are available via the sub-tab bar near the top of the page. All sub-tables support search, sorting, column resize, Export CSV, Delete Selected, and Delete All.

Requires DuckLake: This page needs the DUCKLAKE_PG_URL environment variable set and the ducklake_catalog PostgreSQL database accessible. If analytics are unavailable, the page shows an error message.

Common controls (all sub-tables)

  • Search — Full-text search across all visible columns. Press Enter or click Search.
  • Export CSV — Downloads all rows matching the current search as a CSV file.
  • Delete Selected — Deletes checked rows only. The button shows a count of selected rows.
  • Delete All — Deletes all rows (or all matching the current search). Prompts for confirmation.
  • Edit button — Opens an inline editor for the row's editable fields.
  • Column filter row — Type in any header filter box to narrow the current page client-side.
Tip: Click any truncated cell to expand its full content in a popup modal. Press Esc to dismiss.

Realtime Tab

Shows the latest measurements from real-time fixed sensors: Pointcast, Solarcast, and bGeigieZen devices. These measurements are fetched periodically from the Safecast realtime feed and stored in the realtime_measurements table.

Table columns

ColumnDescription
IDInternal measurement ID.
Device IDNumeric device identifier from the Safecast API.
Device NameHuman-readable device name (click to expand long names).
TubeGeiger tube model (e.g. LND7317, SBM-20).
TransportConnectivity type (WiFi, cellular, etc.).
CountryCountry where the device is located.
ValueRadiation reading in the unit shown in the Unit column (displayed to 4 decimal places).
UnitMeasurement unit (typically cpm or μSv/h).
Lat / LonGPS coordinates of the device (6 decimal places).
Measured AtTimestamp when the sensor recorded the reading.
Fetched AtTimestamp when the server fetched this data from the Safecast API.

Actions

Export CSV Delete Selected Delete All

Use Delete All to purge stale realtime data and let the fetcher repopulate. This table is automatically refreshed by the background fetcher; deletion is safe.

Note: Realtime data is only available when the server is started with the -safecast-realtime flag.

Translations Tab

Manage the UI text strings for all supported languages (30+). Translations are stored in the translations PostgreSQL table and loaded into memory at startup. Edits take effect immediately after clicking Reload into Memory — no server restart required.

Table columns

ColumnDescription
IDInternal row ID.
LangTwo-letter language code (e.g. en, ja, cs).
KeyIdentifier used in templates (e.g. legend_safe, nav_map).
ValueTranslated text in that language. Click the cell or Edit button to edit. Hover to preview long values.
UpdatedUTC timestamp of the last edit.

Actions

+ Add Translation Edit Delete Reload into Memory
  • + Add Translation — Opens a modal to create a new key/language pair. Language code and key are required.
  • Edit — Opens the modal for the selected row. Language code and key are locked; only the value can be changed.
  • Delete — Removes a single translation row permanently.
  • Reload into Memory — Applies all DB changes to the running server without a restart.

Filtering & search

Use the language dropdown to show only one language. Use the search box to filter by key or value text. Both filters work together and apply server-side across all pages.

Important: The string "Safecast" must never be translated (e.g. not チチャ in Japanese). It is a proper noun and must remain "Safecast" in every language.
Tip: Press Ctrl+S (or Cmd+S) while the edit modal is open to save. Press Esc to cancel.
How English fallback works: If a key is missing in a language, the English value is shown automatically. You don't need to add English entries for every language — just translate the keys that differ.

Tour Steps Tab

Manage the guided tour shown to new users when they first open the map. Each step highlights a UI element and shows a tooltip. Steps are ordered and can be enabled or disabled individually.

Table columns

ColumnDescription
⠿ (drag)Drag handle — drag rows to reorder steps. The order is saved immediately on drop.
#Display order number (1 = first step).
Step keyUnique identifier for this step (e.g. upload_btn). Used for translations.
Target selectorCSS selector for the element to spotlight. A pick-element button lets you choose live on the map. Leave blank (with "Center" checked) to show a centered modal step.
TextTooltip text in the currently selected editing language. Edit inline.
ConditionsColored badges showing when this step is visible: Login required, Admin only, Feature gate, Viewport (desktop/mobile), First-time only.
OnToggle switch — green means enabled and shown to users; grey means disabled and skipped.

Actions

+ New step ▶ Preview tour Edit conditions Save text Delete step
  • + New step — Opens the conditions modal in "create" mode. Set the key, selector, and visibility conditions, then save. After creation, edit the text inline in the table.
  • ▶ Preview tour — Opens the map in a new tab and immediately starts the tour so you can see how it looks to users.
  • Edit conditions (orange button) — Opens the conditions modal for an existing step. Conditions include: require login, require admin, feature gate, viewport restriction, and first-time-only flag.
  • Save (green) — Saves inline text edits for a row.
  • Delete — Permanently removes the step.

Language selector

The Editing language dropdown controls which translation is shown in the Text column. Select a language to view and edit the tour text in that language. New languages appear automatically when translations for tour-step keys are added in the Translations tab.

Condition badges

  • Login — Step only shows to logged-in users.
  • Admin — Step only shows to admin users.
  • Feature — Step only shows when a specific feature flag is active (e.g. AI assistant enabled).
  • Viewport — Step only shows on desktop or mobile.
  • First-time — Step only shows during the user's first-ever tour run.
Tip: Drag rows to reorder — the order persists to the database immediately on drop, no Save button needed.

AI Hints Tab

Configure context hints that are injected into the AI assistant's system prompt. Hints improve the AI's domain knowledge and allow tuning of tool behavior without code changes. Hints are grouped by bot (a named configuration profile).

Layout

The page has a two-column layout:

  • Left sidebar — Lists all bot groups. Click a bot to open its editor. Deleted bots are hidden by default; toggle "Show deleted" to see them.
  • Right editor — Four sub-tabs: General, Global rules, Tools, and History.

Bot groups

  • + Add bot — Creates a new bot group. Enter a display name; the model slug (routing key) is derived automatically and locked after creation.
  • Delete — Soft-deletes the bot (it remains in history). Shown in the sidebar with strikethrough when "Show deleted" is on.
  • Restore — Undeletes a soft-deleted bot.

General sub-tab

FieldDescription
Display nameHuman-readable name shown in the sidebar.
Model slugThe MCP routing key (read-only after creation). Derived from the display name.
CapabilitiesTags describing what this bot can do (e.g. radiation_data, realtime). Used for routing and context.
System promptThe base system prompt prepended to every conversation for this bot.

Global rules sub-tab

A list of rule strings appended to the system prompt. Each rule is a plain-text statement that guides the AI's behavior (e.g. "Always cite data sources", "Respond in the user's language").

Tools sub-tab

Per-tool configuration cards. Each MCP tool can have:

  • Description override — Replaces the tool's default description in the AI's tool list.
  • Parameter hints — Key-value pairs giving the AI guidance on how to fill specific parameters.
  • Examples — Sample question → expected tool call pairs to help the AI learn the intended usage.

History sub-tab

An audit log of every change made to this bot, with the kind of change (update, delete, restore, import, snapshot) and a timestamp.

Toolbar actions

Save Reload into Memory Snapshot Export JSON Import JSON Delete
  • Save — Writes changes to the database.
  • Reload into Memory — Re-reads all hints from the database and applies them to the running server without a restart.
  • Snapshot — Manually saves a history checkpoint without changing any data. Useful before making large edits.
  • Export JSON — Downloads the current bot's full configuration as a JSON file.
  • Import JSON — Replaces the current bot's configuration with a JSON file. Prompts for confirmation. A history entry of kind import is recorded.
Important: Always click Reload into Memory after saving changes. Without this step, the running server continues using the previous hints until it is restarted.
Note: The model slug is the key used by the MCP client to route requests to a specific bot. Changing it would require updating the MCP client configuration as well.
