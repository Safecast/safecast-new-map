# Fix CloudFront 403 Error - WAF Blocking Large Uploads

## Problem

Large file uploads (>10KB) return **403 ERROR** from CloudFront with message:
```
Request blocked. We can't connect to the server...
Generated by cloudfront (CloudFront)
```

## Root Cause

AWS WAF (Web Application Firewall) is enabled on the CloudFront distribution and is blocking large POST request bodies with the `SizeRestrictions_BODY` rule, treating them as potential DoS attacks.

**WAF ACL:** `CreatedByCloudFront-92534502`
**Distribution ID:** `E12FYIQ8RRXOJ1` (simplemap.safecast.org)

## Solution (Working Configuration)

Since CloudFront Free Plan doesn't allow custom URI path inspection rules, we changed specific AWS Managed Rules to "Count" mode instead of "Block" mode.

### Step 1: Access WAF Console

1. Go to AWS WAF Console: https://console.aws.amazon.com/wafv2/
2. **Region:** Global (CloudFront)
3. Click on WAF ACL: `CreatedByCloudFront-92534502`

### Step 2: Configure AWS-AWSManagedRulesCommonRuleSet

1. Click **Rules** tab
2. Find rule group: **AWS-AWSManagedRulesCommonRuleSet**
3. Click **Edit** button
4. Scroll to **Rule overrides** section

### Step 3: Change Size Restriction Rules to Count Mode

Change the following rules from **Block** to **Count**:

| Rule Name | Action | Reason |
|-----------|--------|--------|
| `SizeRestrictions_BODY` | **Count** | Allows large POST bodies for file uploads |
| `SizeRestrictions_Cookie_HEADER` | **Count** | Prevents session cookie size blocking |
| `SizeRestrictions_URIPATH` | **Count** | Prevents URI path length blocking |

**Important:** Keep all other rules as **Block** to maintain security:
- `SizeRestrictions_QUERYSTRING` - Block
- `EC2MetaDataSSRF_BODY` - Block
- `GenericLFI_BODY` - Block
- `GenericRFI_BODY` - Block
- `CrossSiteScripting_BODY` - Block
- All other security rules - Block

### Step 4: Save Configuration

1. Click **Save** at the bottom of the page
2. Wait **2-3 minutes** for WAF to update
3. CloudFront will use the new rules immediately (no invalidation needed)

## Security Considerations

**What "Count" mode does:**
- Logs the request but **does not block** it
- Allows monitoring for attacks without blocking legitimate traffic
- Maintains visibility into potential threats

**Why this is safe for Safecast:**
- Application-level authentication protects `/upload` endpoint
- Server is Go-based (not vulnerable to Java/Log4j attacks)
- CloudFront still provides DDoS protection at network layer
- Other WAF rules remain active to block SQL injection, XSS, etc.

**Monitoring:**
- Check WAF logs periodically for suspicious activity
- Review "Count" mode matches in CloudWatch Logs
- Consider upgrading to paid WAF tier for custom URI path rules

## Why Free Tier Doesn't Allow Custom Rules

CloudFront Free Plan WAF limitations:
- ❌ Cannot create custom rules with URI path inspection
- ❌ Cannot add exceptions for specific endpoints
- ❌ Limited to 5 rules total
- ✅ Can override AWS Managed Rules to "Count" mode (what we did)
- ✅ Can disable WAF entirely (not recommended)

## Alternative Solutions Attempted

## Troubleshooting

**If uploads still fail after configuration:**

1. **Check WAF rule status:**
   - Go to WAF Console → Rules
   - Verify `SizeRestrictions_BODY` shows "Count" not "Block"

2. **Clear CloudFront cache:**
   ```bash
   aws cloudfront create-invalidation --distribution-id E12FYIQ8RRXOJ1 --paths "/*"
   ```

3. **Check browser console:**
   - Press F12 → Network tab
   - Attempt upload
   - Look for 403 response
   - Check "Response" tab for error message

4. **Verify session cookie:**
   - Ensure user is logged in
   - Check "Application" → "Cookies" for `safecast_session`
   - Cookie must be sent with upload request

**If you see different errors:**
- 403 with "Please log in" → Session/authentication issue
- 403 with "Generated by cloudfront" → WAF blocking (check rule overrides)
- 502 Bad Gateway → Backend server issue
- 504 Gateway Timeout → Upload too large or server timeout
