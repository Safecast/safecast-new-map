# Radiation interpolation design

## Purpose

Estimate the latent radiation level R(s,t) at an arbitrary geographic
location and time from crowdsourced sensor observations.

The system must return BOTH:
- predicted radiation
- prediction uncertainty

The system must not imply confidence in areas with poor observational support.

## Important characteristics of the dataset

- Measurements arrive continuously.
- Measurements have latitude, longitude and timestamp.
- Many observations occur along tracks generated by one portable detector.
- Adjacent observations on one track can therefore be extremely redundant.
- Different devices may have different measurement uncertainty/bias.
- Observation density varies enormously geographically.
- Historical observations must remain queryable.

## Statistical model

Use local spatiotemporal kriging rather than independent geographic regions.

For prediction at (s,t):

1. Retrieve observations within an appropriate spatial/temporal neighborhood.
2. Construct covariance between observations.
3. Construct covariance between observations and prediction target.
4. Solve kriging system.
5. Return estimate and kriging variance.

The implementation must support interchangeable covariance models.

Spatial and temporal covariance must be represented separately enough that
their parameters can later be fitted independently.

## Locality

"Local" DOES NOT mean dividing Earth into independent regions.

Prediction neighborhoods overlap.

Adjacent prediction locations should normally use almost identical
observation sets.

There must be no hard geographic boundary between models.

Tile calculations should use a halo/buffer beyond the displayed tile.

## Tracks

Multiple nearby observations from the same track must not be interpreted
as independent evidence merely because there are many observations.

Spatial/temporal covariance handles some redundancy.

Preserve:
- track_id
- device_id
- timestamp

The architecture must permit later introduction of track-level and
device-level error terms.

## Uncertainty

Prediction uncertainty means uncertainty in the LATENT radiation field,
not uncertainty in what a hypothetical Geiger counter would report.

High uncertainty should occur when:
- measurements are far away
- measurements are old
- measurements are highly redundant
- sensors are noisy
- there are few independent observations

The UI may eventually use uncertainty to control opacity or suppress
predictions entirely.

## Disaster behaviour

Kriging is NOT the primary disaster detector.

Raw measurements and anomaly detection operate separately.

A sudden extreme observation must become visible immediately rather than
waiting for the interpolation layer.

The architecture must permit a future event mode in which recent
observations receive much greater relevance than historical background.

## Architecture

Keep these responsibilities separate:

ObservationSource
    -> retrieves candidate observations

NeighborhoodSelector
    -> chooses observations relevant to a prediction

CovarianceModel
    -> calculates covariance

KrigingSolver
    -> solves weights / variance

Predictor
    -> coordinates prediction

Map/tile code should depend only on Predictor.

## Performance

Do not construct a covariance matrix over the entire dataset.

Kriging operates on local neighborhoods.

Initial correctness is more important than premature optimization.

Caching / incremental tile recomputation can be added later.

## Testing

Tests must include:

- exact/simple synthetic fields
- uncertainty increasing away from observations
- redundant clustered points not behaving like independent observations
- continuity across map tile boundaries
- temporal decay
- historical predictions
- numerical stability
